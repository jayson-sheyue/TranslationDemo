三件最容易踩坑的事

  • 不是所有模型支持所有语言。先在“检测与语言”查清楚。
  • 术语表和数据集有区域。不确定时先使用 us-central1。
  • 批量任务不会立即完成。它会返回任务编号，稍后到 GCS 输出目录找结果。

SYNCHRONOUS

TranslateText

支持纯文本 / HTML、自动检测源语言、NMT、Translation LLM、Adaptive LLM、AutoML 自定义模型、术语表与标签。

第一次怎么做（20 秒）

  1. “待翻译内容”输入一句无敏感测试文字；每一行会单独翻译。
  2. 源语言不知道就留空；目标语言先保留 zh-CN。
  3. 模型先选 general/nmt，点“翻译”。

什么时候换模型？聊天、按钮、短内容选 NMT；正式文案、客服回复、重质量内容再试 Translation LLM。用同一句话对比后决定，不要盲目选择更贵模型。

DOMAIN CONTROL

Glossary

术语表来自 Cloud Storage 的 CSV/TSV/TMX；创建和删除均为长时间运行任务。翻译时在「文本翻译」填入术语表 ID。

术语表适合什么、不适合什么？

适合：产品名、品牌、岗位名、行业专有词，例如让 Atlas 始终译为“阿特拉斯”。
不适合：想“自动改好整段翻译”。它不是通用纠错工具。

  1. 先在 GCS 上传 CSV、TSV 或 TMX 文件，例如一行 Atlas,阿特拉斯。
  2. 把文件地址填入下方，例如 gs://my-bucket/terms.csv。
  3. 创建成功后，在“文本翻译”填写同一个术语表 ID。

没有 GCS？先跳过本页，基础翻译完全不受影响。

术语表清单将显示在这里。

停止词提示：单独的 the、and 等无效搜索字词会被 Glossary 忽略。

这是本地预检；完整的语言专属列表以官方文档为准。

ASYNC + FILES

批量文本与文档

所有输入输出都在 Cloud Storage。批量文本最多 100 个文件、10 个目标语言；在线文档翻译直接返回二进制输出。

先选对方式，避免白忙

在线文档翻译：翻译你电脑里的一份小测试 PDF、DOCX、PPTX 或 XLSX，适合现在就要下载结果。
批量翻译：翻译很多文件；输入和输出都必须在 GCS。提交后只返回任务编号，稍后到 GCS 输出目录找文件。没有 GCS 就先用在线文档。

Adaptive Translation
用少量领域句对引导 LLM。可在 TranslateText 选择 adaptive LLM，或使用下方 Adaptive MT 数据集接口。

数据集：把很多 TSV/TMX 对照句保存下来，反复用于固定业务，例如客服语气。

PREVIEW
RomanizeText
把日文、韩文等非拉丁文字转换为以发音为准的拉丁文字，不等同于翻译。

      
HYBRID TUTORIAL
图片 OCR + 翻译
参考混合术语表教程：Cloud Vision 先提取图片文字，再交给 v3 TranslateText。需要启用 Vision API；如需术语表，请使用文字翻译实验区。

      
AutoML 自定义 NMT 与 Translation LLM
在 Google Cloud 中训练 AutoML Translation 模型后，把模型 ID 填入文本翻译的「自定义模型 ID」。模型选择器同时提供 general/nmt、general/translation-llm 与 general/translation-llm-adaptive，便于按质量、延迟和领域适配对比。
